* Introduction

=alref= is the spec-reference library shipped with =autolisp-spec=.
It has two parallel surfaces:

- =alref.el= — an Emacs minor-mode + commands
  (=M-x alref-lookup=, =alref-autodoc-mode=).
- =alref.lsp= — an AutoLISP library you can load into any
  conforming runtime (AutoCAD, BricsCAD, clautolisp) for
  interactive use at the AutoLISP REPL.

Both consume the paged spec artefacts produced by
=scripts/build-paged-spec.el= (=build/pages/=, =build/html/=,
=build/info/=) and expose the same vocabulary: look up a symbol
to find its description, search the index by substring, walk
chapter intros, etc.

* Installation

The paged spec data, the Emacs lib, and the AutoLISP lib install
under:

  $(PREFIX)/share/doc/autolisp-spec/           reference org + pdf docs
  $(PREFIX)/share/doc/autolisp-spec/pages/     data files (alref reads)
  $(PREFIX)/share/info/                        autolisp-spec.info
  $(PREFIX)/share/emacs/site-lisp/autolisp-spec/    alref.el
  $(PREFIX)/share/autolisp/site-lisp/autolisp-spec/ alref.lsp

Run =sudo make install= from this subproject to lay everything
down. The default =PREFIX= is =/opt/local=; override on the
command line.

* alref.el — Emacs

After installation, add the site-lisp directory to your =load-path=
(distros usually do this automatically) and:

  (require 'alref)

Then:

- =M-x alref-lookup RET name RET= — completing read over every
  documented symbol, opens the matching HTML page in your browser.
- =M-x alref-autodoc-mode= — buffer-local minor mode that shows
  the operator signature of the symbol at point in the
  minibuffer, like slime-autodoc. Picks up the
  =[A]= / =[B]= / =[C]= / =[ABC]= compatibility tag from the
  symbol's Compatibility section when the page has one.
- Customise the data root via
  =M-x customize-variable RET alref-spec-directory= or set it in
  your init file.

* alref.lsp — AutoLISP

At the AutoLISP REPL, load the library (typically from a user
init file):

  (load "/opt/local/share/autolisp/site-lisp/autolisp-spec/alref.lsp")
  (alref-set-root "/opt/local/share/doc/autolisp-spec/")

Then call:

*Namespaces.* A name lives in up to four namespaces, each with its own
meaning: =FUNCTION= (functions and special forms), =VARIABLE=, =SYSVAR=
(system variables) and =COMMAND= (CAD commands). The same name can be
in several: =LOAD= is a function and a command. A function =C:HELLO=
is in the function namespace as =C:HELLO= /and/ is the command =HELLO=
-- which is not the same thing as a function =HELLO=, if there is one.
Every function below covers all four namespaces; each has four
variants, suffixed =-function=, =-variable=, =-sysvar= and =-command=,
that look in that namespace only.

- =(alref-apropos "pattern")= — print one line per name /and/
  namespace whose name contains PATTERN (case-insensitive), from the
  spec, the live image and the host's system variables; returns the
  number of lines:

    NAME<TAB>Function
    NAME<TAB>Variable<TAB>VALUE          (NIL when unbound)
    NAME<TAB>Sysvar<TAB>VALUE
    NAME<TAB>Command                     (a CAD command the spec documents)
    NAME<TAB>Command<TAB>(C:NAME)        (the command a C:NAME function defines)
    NAME<TAB><spec kind>                 (Reader Syntax, Type ...)

  With =(defun c:hello ...)= and =(defun hello ...)= loaded,
  =(alref-apropos "HELLO")= prints three lines: =C:HELLO Function=,
  =HELLO Command (C:HELLO)= and =HELLO Function=. The spec documents
  every AutoCAD and BricsCAD command (chapter 28), implemented in
  clautolisp or not, and every system variable.
  Variants: =alref-apropos-function=, =alref-apropos-variable=,
  =alref-apropos-sysvar=, =alref-apropos-command=.
- =(alref-apropos-list "pattern")= — the list of matching names,
  each once. Variants: =alref-apropos-list-function= ...
  =alref-apropos-list-command=.
- =(alref-lookup "pattern")= — print the names of
  =alref-apropos-list=, one per line.
- =(alref-documentation NAME)= — the documentation of NAME (a symbol
  or a string) as a string: its spec page, else the live binding's
  documentation (the =;| ... |;= block before its =defun= or =setq=;
  for a command =HELLO= defined by =C:HELLO=, that function's), else
  ="not documented"=; =nil= when NAME is nothing. A name in several
  namespaces gives all its pages, each live one under a header naming
  its namespace (~=== Command: HELLO (function C:HELLO) ===~). A chapter
  number or title gives the chapter. A command's page gives its
  /Availability/ -- AutoCAD and BricsCAD, with their versions, or
  "not documented" -- and its clautolisp status (implemented in the
  cador host, a recognised no-op, or not yet implemented).
  Variants: =alref-documentation-function= ...
  =alref-documentation-command=.
- =(alref-describe NAME)= — print what =alref-documentation= returns,
  every page, a live entry followed by its apropos line;
  =NAME<TAB>Inexistant= when nothing matches. Variants:
  =alref-describe-function= ... =alref-describe-command=.

alref.lsp documents itself the same way: =(alref-documentation
'alref-documentation)= returns its documentation, whether alref.lsp
was loaded from source or from a compiled =.lap=.
In Emacs (=alref.el=) the command of a name that is also a function
completes as =NAME <Command>=.
- =(alref-help "string")= — search the body of every documented
  page for STRING and return the list of matching page
  basenames.

* The [ABC] coverage indicator

The indicator surfaces in two places:

- =alref.el='s =alref-autodoc-mode= shows it at the end of the
  minibuffer signature line.
- (=alref.lsp='s =alref-apropos= does not print it: its lines carry
  the namespace and the live value instead.)

  [A]    spec'd by AutoCAD only
  [B]    spec'd by BricsCAD only
  [C]    implemented in this image only (no spec entry)
  [AB]   spec'd by both vendors, not in this image
  [AC]   spec'd by AutoCAD, implemented in this image
  [BC]   spec'd by BricsCAD, implemented in this image
  [ABC]  spec'd by both vendors AND in this image

The data comes from the per-spec-entry =Availability= section
(parsed at paged-build time into the 4th column of
=symbols.txt=) plus the runtime's =atoms-family= (for the C bit).

* Re-building the data

After editing the canonical spec
(=autolisp-visual-lisp-specification-draft.org=), regenerate
the paged artefacts:

  make pages           ## emits build/pages/*.txt + symbols.txt + index.txt
  make html            ## emits build/html/*.html
  make info            ## emits build/info/autolisp-spec.info
  make documentation   ## also rebuilds the PDF

=make install= ships every artefact.
