* Processing rules

- If an issue is completely done, close it and move it to =issues/closed/=.
- Process issues in the priority order below (P1 → P2 → P3); within a
  tier, =NEXT= first, then =TODO=; skip =BLOCKED= / =DEFERRED=.
- Strive to implement an issue completely. Only inconsistency or a
  dependency (missing spec, or another issue's implementation) justifies
  putting it on hold and moving on.
- Before starting, check the tree: progress may have made parts (or all)
  of an issue irrelevant — then close it with an explanation.
- Non-blocking bugs found mid-issue: enqueue as a new issue (standard
  format below) and add it here. Blocking bugs: fix within the current
  issue (may be a separate commit).
- Branch naming: bug → =fix-<slug>=, feature → =feature-<slug>=; an epic
  runs in one long-lived branch for its sub-issues. Fetch + rebase before
  merging back to =master=.

* Standard issue format

Every issue file is =<slug>.issue=, org-mode, UTF-8, beginning with the
keyword header below; new issues MUST use it, existing ones are
retrofitted as they are touched.

#+begin_src org
  # -*- mode:org; coding:utf-8 -*-
  #+TITLE: <slug> — <one-line summary>
  #+STATUS: NEXT|TODO|BLOCKED|DEFERRED|DONE|WONTFIX
  #+PRIORITY: P1|P2|P3
  #+TYPE: bug|divergence|cad-runtime|feature|epic|spec|infra|doc
  #+DEPENDS: <issue slug(s) or external gate, or ->
  #+BRANCH: fix-<slug> | feature-<slug> | <epic-branch>
  * Context
  * Problem
  * Proposal
  * Acceptance criteria
#+end_src

=BLOCKED= records *why* in =#+DEPENDS:= (e.g. =bricscad-access=,
=windows-access=, =pjb-decision=, =libredwg-upstream=, or an issue slug).
