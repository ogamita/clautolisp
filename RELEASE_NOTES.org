* About this file

This file records every user-visible feature shipped by the programs
that =make install= places under =$PREFIX= (default =/opt/local=).
Read it to know what each program does and where to find the full
reference. Each entry is intentionally short — one to three lines —
and points at the relevant ~user-manual.org~ for normative details.

This is not a changelog. Each section reflects the *current* state of
master at the top of the file (clautolisp 1.8.55 / alfe 1.8.4 /
read-autolisp 1.8.0). For the
chronology and the issue-by-issue history, see ~git log~ on master and
the issues under ~issues/closed/~.

A standing rule lives in ~AGENTS.md~ § /Release notes/: this file
*must* be updated in the same commit as any user-visible feature
addition or change, including optimisations the user can observe (e.g.
faster startup, lower memory, narrower diagnostic output). Internal
refactors with no user-visible effect do not require an entry.

* clautolisp / read-autolisp (=clautolisp/documentation/clautolisp-user-manual.org=)

clautolisp is a Common-Lisp-hosted AutoLISP interpreter shipped as a
standalone CLI. read-autolisp is its tokenizer/reader available as a
separate binary for tool integrators.

- Native Windows LibreDWG builds select the MSYS2 MINGW64 compiler,
  expose its runtime directory to compiler subprocesses, reject private
  UCRT dependencies, and install the exact DLL imported by the CFFI shim.
- Documentation builds now locate MSYS2 UCRT64 TeX/Graphviz tools and use
  Windows-compatible Kpathsea paths. They also translate Windows-form
  temporary-directory variables before starting POSIX Emacs, allowing
  ~make documentation~ to run from plain MSYS and Emacs shells.
- The published PDFs no longer drop characters. XeLaTeX has no automatic
  font fallback, so a glyph the body face lacks is simply omitted from a
  PDF that still builds successfully — two characters were being lost
  from the sedit specification that way, one of them only inside code
  spans, because ~=code=~ is rendered through the mono face. Both are
  mapped now, and ~make check-doc-glyph-coverage~ fails the build when a
  documentation source uses a glyph the PDF would drop, so the next one
  is caught before it is published rather than after.
- On Windows, ~make install~ now appends ~.exe~ to every executable it
  places under =$PREFIX/bin= and =$PREFIX/libexec= (clautolisp,
  read-autolisp, alfe, the Qt GUI, run-file-compat), and ships the
  bare-name launcher (=clautolisp.exe=, =alfe.exe=, …) as a real copy
  rather than an MSYS symlink — so the installed programs run from
  PowerShell and cmd, not only from the MSYS2 shell. POSIX installs are
  unchanged (no suffix, relative symlinks).

- Paths whose case does not match the disk can be resolved and
  normalised. ~(setvar "CLAUTOLISPCASEINSENSITIVEPATHS" 1)~ — or the
  environment variable of the same name, for a whole corpus — makes
  ~load~, ~open~, ~findfile~, the ~vl-file-*~ functions,
  ~vl-directory-files~ and ~vl-mkdir~ validate every incoming path
  against the filesystem without regard to case, and return real names.
  This is what lets an AutoLISP corpus developed on Windows or macOS run
  on Linux unmodified: those filesystems fold case, so such a corpus
  arrives with its path spellings never once checked. Creating is not
  resolving — the last component of a file being created is taken as
  written, so ~(open "Rapport.txt" "w")~ never lands on a pre-existing
  ~RAPPORT.TXT~ — and two entries differing only by case are an error
  naming both, not an arbitrary pick. A ~[path-case]~ diagnostic names
  the real spelling whenever one was folded, so the run proceeds *and*
  the wrong path is reported rather than hidden. Off by default: at 1 a
  program reaches files an exact spelling would not have.
  See § /Paths whose case does not match the disk/.

** Standalone CLI (clautolisp-sbcl / clautolisp-ccl)

- Three modes: file (~clautolisp file.lsp~), expression (~-x EXPR~),
  and interactive REPL. See § /Modes of Operation/.
- REPL comma-commands: a line starting with =,= is a command, not an
  expression — =,d=/=,date=, =,u=/=,uptime=, =,h=/=,help=, =,q=/=,quit=
  (exit even when ~(quit)~ is not available). An empty line just
  re-prompts. Backed by the interactor framework's command dictionaries
  (the debugger dictionary mechanism, generalised). See § /Modes of
  Operation / Interactive REPL/.
- Session dribble: ~--dribble~ / ~--dribble=FILE~ (or ~(clal-dribble
  [file [interactors]])~ at runtime, a toggle) records the REPL
  interactions into an append-mode log — input raw, output/error
  lines as =;; O:= / =;; E:=, condition reports as =;; C:=, under a
  =;; H: clautolisp VERSION= header. Filtered by interactor:
  ~AUTOLISP~ only by default (a debugger/sedit stop pauses the
  recording); ~--dribble-interactors=t|NAMES~ /
  ~*CLAL-DRIBBLE-INTERACTORS*~ widen the set. Default file:
  =$XDG_STATE_HOME/clautolisp/dribbles/YYYYMMDDTHHMMSS.log=. See
  § /Modes of Operation / Interactive REPL / Recording the session/.
  Prompts are never recorded, including the one left pending when the
  session ends — dribble files no longer finish with a stray =;; O: _$=.
  Output that genuinely ends without a newline (a closing ~princ~) is
  still recorded: the two are told apart because the interactor loop
  says which it is writing, not by guessing after the fact.
- ~(clal-save-aldo-configuration)~ writes the same self-documenting
  =aldo.conf= that ~,settings save~ writes at =DBG>= — the header, the
  settings you set, then every other setting commented out at its
  default with the values it accepts. Saving from AutoLISP used to strip
  that documentation out of a file you may have been editing by hand.
  It still saves what the AutoLISP variable holds; only the form changed.
- A line whose *first* character is ~!~ sends the rest to your ~$SHELL~
  with stdin/stdout/stderr *inherited*, so an interactive command can
  prompt, page or draw — which ~startapp~ cannot do. Nothing may precede
  the ~!~; a trailing ~&~ gets ~echo $!~ appended so the PID is printed;
  a trailing backslash continues the command on the next line. The
  character is the ~shell-escape-character~ setting of ~lisp.conf~ and
  is in force in the debugger and the editors too. See § /Modes of
  Operation / Interactive REPL / Running a shell command/.
- Five dialects selectable via ~--strict~ / ~--autocad~ /
  ~--bricscad~ / ~--clautolisp~ / ~--lax~. The ~lax~ dialect silences
  every encoding-dispatch diagnostic globally. ~--list-dialects~ prints
  every accepted name, strict first and lax last, so the versioned
  vendor spellings need not be guessed. See § /Options /
  Dialect selection/.
- ~(setq *AUTOLISP-DIALECT* 'DIALECT)~ switches the dialect live: the
  REPL reader and the debugger's / inspector's form reads consult the
  variable at each read (one shared reader entry,
  ~issues/open/interactor-design-revision.issue~ D2), so a mid-session
  switch takes effect on the very next line.
- Predefined variables: the three the spec classifies as such are bound
  at startup — ~pi~ (the real 3.141592653589793, so ~(* 2 pi r)~ /
  ~(/ pi 2)~ work; it read as nil before), ~pause~ (the ~(command …)~
  interaction token), and ~T~ (bound to itself, so ~(boundp 'T)~ and
  ~(vl-symbol-value 'T)~ now report it bound as in AutoCAD, in addition
  to self-evaluating). All three remain ordinary, user-settable.
- Host backend selectable via ~--host cador|nihil~ (default cador — the
  headless in-process CAD core; ~nihil~ is the trivial no-CAD backend).
  ~mock~ is a deprecated alias of ~cador~; ~null~ / ~none~ of ~nihil~.
- *Entity model* (mock host): the low-level entity family works end to
  end against an in-memory drawing database. ~entmakex~ returns the new
  entity's ENAME (feedable straight into ~entget~/~entmod~/~entdel~),
  ~entmake~ returns the supplied list (vendor echo) and both validate the
  required DXF group codes of the modelled families — LINE, POINT,
  CIRCLE, ARC, ELLIPSE, LWPOLYLINE, POLYLINE (+VERTEX/SEQEND), SPLINE,
  TEXT, MTEXT, ATTDEF, ATTRIB, INSERT, 3DFACE, SOLID, TRACE, RAY, XLINE,
  XRECORD — returning ~nil~ + ~ERRNO~ 36 on a bad create (never a raised
  error), any other type accepted permissively. ~entget~ takes the
  application filter (~(entget ename '("APP"))~) to surface xdata, which
  is otherwise suppressed; ~entmod~ replaces ordinary codes and edits
  xdata per application; ~entdel~ is the within-session delete/restore
  toggle; ~entnext~/~entlast~ walk main entities and subentities, with a
  POLYLINE/INSERT stamping its VERTEX/ATTRIB/SEQEND pieces' owner (group
  330). A portable ~.lsp~ probe under
  ~autolisp-front-end/tests/scenarios/entities/~ runs the full lifecycle
  unchanged under clautolisp and (via alfe) on BricsCAD/AutoCAD.
- *Drawing-data structures* (mock host): ~regapp~ registers an XData
  application (APPID); XData round-trips losslessly through
  ~entget~/~entmod~ across the full group-code set
  (1000/1001/1002/1003/1004/1005/1010–1013/1040/1041/1042/1070/1071),
  order and multiplicity preserved. The named-object-dictionary tree is
  live — ~namedobjdict~, ~dictadd~, ~dictsearch~, ~dictnext~,
  ~dictremove~, ~dictrename~, ~dictobjname~ — with XRECORD objects
  created by ~entmakex~, mutated by ~entmod~, enumerated and deleted;
  duplicate/absent keys fail soft (nil), never a raised error. The full
  standard symbol-table set — LAYER, LTYPE, STYLE, BLOCK, VIEW, UCS,
  VPORT, DIMSTYLE, APPID — answers ~tblsearch~/~tblnext~/~tblobjname~,
  with record string values returned AutoLISP-wrapped so ~strcat~/~=~
  accept them. Drawing-scoped system variables are isolated between
  fresh sessions. A portable ~drawing-data-probe.lsp~ covers the whole
  surface.
- *Selection + snapshot* (mock host): the non-interactive whole-database
  scan ~(ssget "X"/"_X" [filter])~ over the active drawing, returning
  graphical entities only (dictionaries/xrecords excluded). Full filter
  grammar: attribute tests on any code, WCMATCH wildcards and
  comma-alternation (group 8 layer lists), the ~-3~ XData application
  filter (wildcard app names), and the ~-4~ relational
  (~= /= != < > <= >= & &= *~) and logical (~<AND>/<OR>/<NOT>/<XOR>~)
  operators. ~sslength~/~ssname~/~ssadd~/~ssdel~/~ssmemb~ with
  duplicate-safe membership; ~entnext~/~entlast~ as the traversal
  fallback. ~(ssget "_I" [filter])~ returns the *implied* (pickfirst)
  selection set — the read side of ~sssetfirst~ — sharing the ~"_X"~
  filter grammar; it never prompts, honours ~PICKFIRST~ (0 → nil), and
  is consumed on read (a second read without an intervening
  ~sssetfirst~ returns nil), matching the vendors. The remaining
  interactive/graphical modes ((ssget) pick, ~_C/_W/_CP/_WP/_F~, grip
  highlight) are out of scope and fail cleanly (a
  catchable AutoLISP error), never a crash. A portable
  ~selection-probe.lsp~ fences its assertions to its own entities via an
  XData filter, so they hold on a non-empty drawing and test set
  membership, not enumeration order.
- ~vl-registry-read/-write/-delete/-descendents~ are host-backed and
  *persistent* on the mock host ($XDG_CONFIG_HOME/clautolisp/
  registry.sexp — the Windows-registry / macOS-defaults emulation):
  values survive across runs, keys are case-insensitive backslash
  paths, a nil value-name is the key's default value, and
  ~vl-registry-descendents~ returns immediate sub-keys by default
  (value names with the flag).
  Mock-host carries the full 1836-entry vendor sysvar catalogue.
- Under ~--bricscad~ the sysvar *set* matches BricsCAD: the 382
  catalogue variables BricsCAD does not define (confirmed by both the
  inventory and a live BricsCAD V26 probe) are dropped, so ~(getvar
  "DYNPROMPT")~ returns ~nil~ and ~(setvar …)~ errors, as on a real
  BricsCAD. Other dialects keep the full AutoCAD-derived catalogue.
  Engine identity (~PROGRAM~ / ~ACADVER~ / …) and the dynamic codepage
  sysvars are unaffected. See
  ~issues/open/bricscad-dialect-sysvar-parity.issue~.

** Dialect portability warnings (autolisp-spec ch.25)

- A non-portable construct still *runs* under clautolisp but emits an
  advisory ~[lambda-list-extension]~ WARNING to stderr when the active
  dialect targets a host that lacks it. First consumer: a ~defun~ /
  ~lambda~ ~&rest~ parameter (a BricsCAD extension AutoCAD does not
  support) — silent under ~--bricscad~ / ~--clautolisp~ / ~--lax~,
  warns under ~--strict~ / ~--autocad~.
- ~(vl-catch-all-apply f)~ — the argument list may be OMITTED, and is
  then taken as empty. *Both engines accept it*, measured rather than
  assumed: BricsCAD V26 relies on it in its own shipped
  ~vle-extension.lsp~, and an AutoCAD 2022 probe run returned the value,
  giving the engine's own arity error when the called function needed an
  argument. Autodesk's documentation calls the argument required — the
  documentation is what was wrong.
  ~--strict~ still emits ~[vl-catch-all-apply-arity]~: not because the
  engines disagree, but because neither /documents/ the tolerance, and
  strict means the documented subset. Silent under ~--autocad~,
  ~--bricscad~, ~--clautolisp~ and ~--lax~.
- Once per occurrence: each source site warns at most once per run, on
  its first evaluation — a loop around the same ~defun~ warns once, a
  guarded/never-evaluated ~defun~ never warns, and a *different* ~defun~
  warns independently. Warnings go to stderr, which a normal run
  surfaces.
- Optional warning→error escalation via the dialect
  ~:portability-warning-mode :error~ knob (default ~:warn~), mirroring
  ~:unbound-variable-mode :strict-error~; off unless opted in.
  See ~issues/open/clautolisp-dialect-portability-warnings.issue~.
- One knowledge base. Every portability decision now comes from a
  single catalogue
  (~clautolisp/autolisp-runtime/source/portability.lisp~) instead of
  per-emitter ~case~ forms: each entry records the construct, the
  dialects whose host provides it natively, the dialects that stay
  quiet anyway, and the evidence behind the entry. Fixing a side
  effect of the old arrangement, ~let~ is now correctly silent under
  ~--dialect bricscad-v25~ as well as ~bricscad-v26~.
- Constructs clautolisp *deliberately* does not implement now say so.
  Calling BricsCAD's ~setf~ or ~let*~ is still an undefined-function
  error, but a ~[ext-bricscad-undocumented]~ note now precedes it
  explaining the refusal — ~setf~ on BricsCAD returns a constant
  sentinel ~2~ and does not assign, and ~let*~ does not exist on
  BricsCAD either. Unlike the advisory warnings this note is not
  dialect-gated: the error fires everywhere, and a ~--dialect bricscad~
  user is the likeliest to be surprised.

** Encoding handling (issues/closed/encoding-dispatch.issue)

- Launch chain: =LC_ALL → LANG → LC_CTYPE → -Esource= resolves the
  active encoding at startup and populates ~SYSCODEPAGE~, ~DWGCODEPAGE~,
  and ~*AUTOLISP-FILE-ENCODING*~ (no more empty placeholders). Empty-
  string sentinel for ~*AUTOLISP-FILE-ENCODING*~ in the degenerate
  case (no locale env, no ~-Esource~) falls through to the dialect
  default. See § /Source-file and terminal encoding/.
- Encoding is set per *situation*: ~-E<situation>[-<dir>] ENC~ /
  ~--<situation>-encoding ENC~ (~source~ / ~file~ / ~console~ /
  ~cadstdio~ / ~log~ / ~terminal~; bare ~-E~ sets all), replacing the
  old ~-e~ / ~-E~. ~--list-situations~ prints them.
- ~LOAD~ and ~OPEN~ accept a positional ~[encoding]~ argument under
  ~--clautolisp~ / ~--lax~. Foreign-dialect spellings (AutoCAD's
  ~"utf8"~ / ~"utf8-bom"~ third arg, BricsCAD's ~,ccs=…~ mode suffix,
  ~LISPSYS~) work under their native dialect; other dialects emit
  ~enc-foreign-dialect~ but still honour the call.
- Diagnostic codes: ~enc-foreign-dialect~, ~enc-extension-used~,
  ~enc-unsupported-target~, ~enc-invalid-value~,
  ~enc-lispsys-out-of-range~, ~enc-codepage-mismatch~,
  ~enc-unknown-codepage~, ~enc-host-dependent~. See § /Errors and
  Diagnostics / Encoding-dispatch diagnostics (enc-*)/.
- The named code pages work the same on every host. Where the
  underlying Common Lisp ships no codec — CCL has none for CP-1252,
  CP-1250/51/53/54 or KOI8-R, so ~(open f "w" "CP-1252")~ used to
  succeed on SBCL and signal on CCL — clautolisp supplies its own.
  ~--list-encodings~ names them in a /Provided by clautolisp/ section
  (absent on a host that needs no help). See § /Which encodings you
  actually get/.
- Encoding names the hosts spell differently are normalised, so the
  spelling you type no longer decides whether the call works. Every
  Mac Roman spelling — ~"mac-roman"~, ~"MACROMAN"~, ~"mac_roman"~,
  ~"macintosh"~, ~"x-mac-roman"~, ~"CP-10000"~ — resolves to the
  external format both hosts accept, on ~-e~ / ~-E~, ~OPEN~ and
  ~LOAD~ alike. This makes ~(setq *AUTOLISP-FILE-ENCODING* (getvar
  "SYSCODEPAGE"))~ work on macOS, where BricsCAD reports
  ~"MAC_ROMAN"~. See § /Encoding names the hosts spell differently/.

** clautolisp-only helpers (CLAL-* prefix)

- ~clal-command-log~ — the ~command~ / ~command-s~ / ~vl-cmdf~ token
  sequences routed to the host this session, oldest first. Under the
  MockHost (no command engine) the recorded log is the whole
  observable effect of a ~command~ call — the deterministic
  assertion surface for headless rigs. See § /clautolisp
  Extensions/.
- ~clal-sysvar-list~, ~clal-sysvar-apropos~ — discover the active
  host's system variables.
- ~clal-system-codepage~, ~clal-drawing-codepage~,
  ~clal-codepage-mismatch-p~ — canonicalised SYSCODEPAGE / DWGCODEPAGE
  query for defensive comparison.
- ~clal-file-encoding PATH~ — sniff the BOM, return one of
  ~"UTF-8-BOM"~ / ~"UTF-16-LE"~ / ~"UTF-16-BE"~ / ~"UTF-32-LE"~ /
  ~"UTF-32-BE"~ / ~"ANSI"~. See § /clautolisp Extensions/.
- ~clal-common-lisp~ / ~clal-back~ — drop into a live Common Lisp REPL
  inside the running image, and return from it. Unavailable until the
  ~CLAUTOLISPDROP~ sysvar is set non-zero, so a program cannot fall into
  it by accident. ~*clal-on-error*~ chooses what an unhandled CL error
  does. See § /clautolisp Extensions/.
- ~clal-optimize~ / ~clal-optimization~ — read and set the optimization
  qualities. ~DEBUG~ above 0 is what makes breakpoints and stepping
  possible; ~SPEED~ is pinned at 0 until the compiler tier exists.
- ~clal-compile~, ~clal-module-extension~ — compile a lambda form, and
  ask which file extension this host uses for a packaged artefact
  (~.lap~ / the OS shared-library suffix) instead of guessing.

** sedit — structural editor + clipboard (=clautolisp/documentation/clautolisp-sedit-spec.org=)

- ~(clal-sedit [object])~ — edit a form with the *sedit* structural editor: no
  argument starts at ~nil~; a symbol recalls its recorded definition; a string
  is a file or directory path; any other value is edited as a sexp. Two-mode
  (navigate / edit) with motions, insert/add/replace, wrap/slurp/barf/splice/
  split/join, one-level undo, and byte-preserving formatting. Returns the edited
  object. See the new manual chapter § /sedit and the aldo form navigator/.
- The interactive REPL now records every top-level form it evaluates, so
  ~(clal-sedit 'NAME)~ recalls a function/variable you defined at the prompt.
- *Clipboard* (system-clipboard aware, degrades to in-process only):
  ~(clal-clipboard-copy-sexp OBJ)~ / ~(clal-clipboard-paste-sexp)~ and the text
  forms ~(clal-clipboard-put-text S)~ / ~(clal-clipboard-get-text)~. Paste never
  evaluates its input. Providers: X11, Wayland, macOS, Windows, OSC 52, NULL.
- From the aldo form navigator, an editing word (=edit=, =insert=, =wrap=, …)
  opens the same editor on the current function; leaving it installs the edited
  definition in the running system (spec §7).
- A bare Lisp *form* typed at any prompt — =DBG>=, the form navigator =NAV>=, or
  the editor =SEDIT>= — is evaluated and its result printed, like the REPL.
- =,settings NAME= now reports an error for an unknown setting name instead of
  printing a bogus value.
- The Lisp REPL has its own persistent configuration, and configurations stack
  the way interactors do: =,set= lists the REPL's settings (marking which are
  still at their built-in default), =,set NAME VALUE= changes one, and
  =,write-settings= writes =$XDG_CONFIG_HOME/clautolisp/lisp.conf=. Its first
  setting is ~sedit-on-quit~, governing ~(clal-sedit …)~ from the REPL while
  aldo's setting of the same name governs debugger-side invocations. At the
  REPL only =lisp.conf= is active; inside the debugger both are, aldo over lisp
  — so a setting you put only in =lisp.conf= is honoured at =DBG>= too. Writes
  always go to the active interactor's own file. Both files now record only
  what you explicitly set, so they read as a diff against the defaults. See §
  /Settings and configuration/.
- A saved =aldo.conf= / =lisp.conf= now *documents itself*: under the settings
  you changed, every setting you left alone is written out commented, at its
  built-in default and followed by the values it accepts — so the file can be
  edited by hand without the manual beside it. The commented lines are
  documentation, not data: they are skipped by the reader, so loading such a
  file still sets only its live entries and the aldo-over-lisp stacking is
  unaffected. Saving rewrites the file, so comments you add by hand are not
  kept. Symbols in both files are also written plainly again
  (=(navigator . line)=, not =(|navigator| . |line|)=). See §
  /Editing a configuration file by hand/.
- *The vl-registry backend works on a localised Windows.* =reg.exe= answers
  in the console OEM code page (CP850 in western Europe, CP437 in the US),
  not UTF-8 — and decoding that as UTF-8 does not garble, it *signals*: the
  offending byte 130 is the =é= of "Opération terminée avec succès",
  =reg.exe='s own success message. Every registry operation therefore aborted
  on such a host, including the write path, which was dying while decoding
  output it discards. The helper's output is now decoded with the console
  code page when the running Lisp knows it (SBCL knows CP437 and CP850), and
  otherwise with LATIN-1, which is byte-transparent and cannot signal.
- *Dialect warnings are now one short line with a place, and a register
  behind them.* A diagnostic reads
  =[lambda-list-extension] drawing.lsp:12 in COMPUTE-AREA: DEFUN `&REST': rest parameter not portable to strict=:
  the bracketed *tag* is the stable identifier, followed by
  =FILE:LINE in FUNCTION= (the function is always reported; the file and
  line need the source map, i.e. a debug load) and one short sentence.
  The former "use =--dialect X= to silence" tail is gone from the runtime
  line — it was the same for every occurrence — and now lives in the new
  annex /Dialect portability warnings/, shipped with the manual, which
  documents all *18* tags: what each construct is, exactly how each
  engine diverges, why it matters, and the references. The annex is
  GENERATED from the same register the diagnostics are formatted from, so
  the two cannot disagree; =make check-dialect-warnings-annex= fails if
  the shipped annex goes stale. Three of those tags
  (=enc-invalid-value=, =sec-untrusted-load=, =sec-untrusted-open=) never
  appear as literals anywhere in the sources — their families build the
  bracket from a code keyword — so a test walks the closed code sets
  instead, and fails when a code is added without an entry.
- The public =*clal-*= extension variables (=*clal-clipboard*=,
  =*clal-sedit-initial-form*= / =*clal-sedit-last-result*=, the =*clal-form*= /
  =*clal-result*= / =*clal-source-form*= eval-history trio and their =-1= / =-2=
  generations, =*clal-on-error*=, =*clal-aldo-configuration*=) are now *bound* at
  startup, so AutoLISP code can read them and =(alref-apropos "*CLAL-")= lists
  them; =clal-clipboard-copy-sexp= and =clal-clipboard-put-text= both set
  =*clal-clipboard*= (so it reflects the write even when the system clipboard is
  unavailable or does not persist the value), and =clal-sedit= sets
  the sedit variables. Each sedit evaluation (=e=, =macroexpand=, or a bare form
  at the prompt) *shifts* the history variables (spec §5.6): =*clal-form*= /
  =*clal-source-form*= / =*clal-result*= hold the most recent, with the =-1= /
  =-2= generations holding the two before — a clautolisp analogue of Common
  Lisp's =+= / =*= REPL variables.

** aldo debugger — form navigator (=clautolisp/documentation/clautolisp-sedit-spec.org=)

- A navigated form with *no source file* (e.g. one defined with
  ~clal-compile~) is now laid out by the AutoLISP indentation rules — newlines
  by special operator, two-space body indent (sedit-spec §5.2, the same layout
  sedit gives it) — with the selection marked, instead of one flat line. The
  same applies to sedit's own selection display: the spine down to a deep
  selection keeps the layout instead of flattening (=format-marked=, =reflow=
  in the =clautolisp.sedit= API).
- The navigator no longer *re-renders the whole view after every command*: an
  output-only turn (a stacked debugger command, an evaluated form, help) just
  prints its output; a bare =RET= redisplays. Motions and edits still redraw.
- With =set navigator sexp= (the default) *every stop* — breakpoint, step,
  error — now enters the sexp form navigator directly, anchored on the current
  poll-point (sedit-spec §7): no =nav= command needed. The flat source-line
  window (the *line* navigator's display) no longer also prints there; =q=
  drops to the flat =DBG>= command loop. With =set navigator line= the stop
  keeps the flat window at =DBG>=.
- Entering the form navigator (=nav=, =g NAME=, =(clal-nav-function 'NAME)=)
  now selects the function's *first poll-point*, not the whole ~defun~ head —
  and, when entered on a *break*, re-anchors to the *current* poll-point (the
  form the debugger stopped on), not the first (sedit-spec §7 re-entry).
- The form navigator's prompt is now plain =NAV>= in every case, never
  =NAV[code]>= / =NAV[non-code]>= — one prompt per mode (=DBG>= debugger, =NAV>=
  navigator, =SEDIT>= editor; sedit-spec §6). A bare form evaluated at the =NAV>=
  prompt is echoed with =NAV>= too, not =DBG>=.
- In navigation mode the navigator keys (=d u > < << >> ±N=) are stacked over
  the full debugger dictionary: every non-motion command — =c i n o a r j=,
  the breakpoint / frame / inspection verbs — dispatches directly, and =?=
  lists them. (The former =i k jj j l ll= letter aliases are retired: they
  shadowed debugger verbs.)
- Interactor routing in the navigator: =aldo CMD= / =debug CMD= (=debug= is
  the debugger interactor's alias) route CMD to the debugger explicitly —
  dispatching normally, user commands first (e.g. =aldo b LOC= while bare
  =b= breakpoints the selection) — the same prefix the sedit editor uses.
- The debugger's built-in vocabulary is now itself a command dictionary
  (the interactor framework): user commands live in a separate dictionary
  layered over it, so they can shadow any built-in.
- One AutoLISP registration API for every interaction mode
  (~issues/open/interactor-design-revision.issue~ D6/D7):
  =(clal-define-command "INTERACTOR" NAMES FN [DOC])= registers a user
  command of the named interactor's user dictionary —
  =(clal-list-interactor-names)= lists the valid names (=ALDO=, =NAVI=,
  =LAVI=, =INSPECT=, =AUTOLISP=) — and commands install before their
  interactor is activated. There is no global user table: a "global"
  command is one defined on the =AUTOLISP= interactor at the bottom of
  the stack. =clal-define-debugger-command= is deprecated, the
  equivalent of =(clal-define-command "ALDO" …)=.
- The REPL is the =AUTOLISP= interactor (alias =LISP=), and it really
  is at the bottom of the stack: at a debugger stop the whole ambient
  stack stays reachable, so a user command registered on =AUTOLISP=
  dispatches from =DBG>= / =NAV>= by fall-through, and =lisp CMD= /
  =autolisp CMD= route to it from any inner mode (at the REPL itself,
  invoke it as =,CMD=).
- sedit is the =SEDIT= interactor (sedit-spec §6.6 amendment, Option A):
  ONE dictionary — motions over *all* sub-sexps plus the editing
  commands — under a single =SEDIT>= prompt; the internal NAV/EDIT
  two-mode machine is gone. =(clal-sedit …)= pushes it over the REPL
  and returns the edited object when =q= pops it; an editing word at
  =NAV>= pushes it over the navigator and the stop. SEDIT's keys shadow
  same-key debugger verbs (=aldo CMD= reaches them); unshadowed
  commands fall through; =aldo c= from inside the editor resumes.
- Quitting *at a stop* now asks: =q= at =NAV>= or =SEDIT>= above the
  debugger warns that quitting aborts the debugged execution, lists the
  resume alternatives, and asks =really abort? (y/n)= — =y= runs the
  debugger's own =quit=, anything else keeps debugging
  (interactor-design-revision.issue T4).
- The =command= word (like bash's =command foo=) is the systematic escape to
  a shadowed built-in: =command CMD= / =aldo command CMD= skip the user
  commands — how a shadowing user command calls the system one. =debugger
  CMD= remains as the historical spelling. See the command reference §8
  /Command dictionaries (stacked dispatch)/.
- A wrong command no longer drops the debugger
  (=issues/closed/error-while-debugging.issue=): at an *error stop*,
  =i=/=n=/=o=/=a=/=j= refuse with the §10.1 guidance instead of silently
  declining the stop (which let the error unwind to the toplevel handler);
  an error escaping any command body is reported (=error while executing
  CMD=) and the stop keeps reading — a debugging state is only dropped by
  an explicit =q=. An AutoLISP error raised while a command evaluates user
  code still breaks into a nested debugger stop first.
- =r='s expression is now *mandatory* (every AutoLISP function returns
  something): a bare =r= prompts =return value?=; a blank answer cancels.
- Correctness after a *caught* error
  (=issues/closed/usubr-arity-error-pops-callers-frame.issue=): a caught
  wrong-number-of-arguments error (=vl-catch-all-apply=, a debugger
  resume) used to pop the *caller's* dynamic frame, so the caller's
  variables silently resolved to stale outer values from then on (the
  reported infinite =fact= recursion). The frame push/pop now pairs
  exactly.
- One loop for every interaction mode (=issues/open/interactor-unification.issue=):
  the debugger prompt, the form navigator, the line navigator, the
  inspector and the REPL all run on the interactor framework's single
  INTERACTOR-LOOP, with their vocabularies as stacked command
  dictionaries. User-visible effects: from the *line* navigator and the
  *inspector* every unshadowed debugger command now works directly (the
  spec §8 stacked dispatch — e.g. =c= continues from inside the
  inspector; its =b= stays =bind=), a bare =(FORM)= evaluates in the
  inspector too, ±N is the =skip= command everywhere, and =aldo CMD= /
  =command CMD= routing works in every mode. Inspector arguments are
  whitespace-separated (=d 0=, =e (+ 1 2)= — no glued =d0=).
- =(clal-nav-function 'NAME)= at the REPL opens the navigator *without* faking
  a break, so you can browse a function and place breakpoints before it runs.
- *Virtual breakpoints* on a file *not loaded yet*: browsing such a file
  (=(clal-nav-file PATH)=, or descending from =(clal-nav-directory)=) and
  pressing =b= on a form records a virtual breakpoint — kept *relative to its
  top-level =defun=* so it survives the file being edited above the form —
  that is *armed automatically* when the file is loaded and the function
  instrumented, firing on the very first post-load run. =lb= lists pending
  records as =vbN=; =delete vbN= removes one. See the command reference §2
  /Virtual breakpoints/.
- The directory browser's =directory-listing= setting now honours =column=:
  an ls -C-style column-major grid (=short= = ls -1 and =long= = ls -l as
  before), still under =directory-window= elision. See the command
  reference §8.
- Setting a breakpoint twice on one poll-point is idempotent — one breakpoint,
  one decoration ("already set" on the repeat). See the three
  =issues/open/bug-aldo-*= tickets.
- *Debugger CLI options* (=issues/open/debugger-public-interface-and-on-error.issue=
  Parts B-D; user manual § /Options / Debugger (aldo)/): the three event
  policies =--on-error quit|debug|ignore= (default: =debug= at the
  interactive REPL, =quit= in batch), =--on-interrupt debug|ignore|quit=
  (default =debug=: Control-C breaks into aldo at the interrupt point;
  =ignore= resumes; =quit= exits 130; a second C-c while one is handled
  exits immediately — on the Windows SBCL build, which lacks the
  POSIX-signal API, this policy has no effect and the native console
  Control-C behaviour is kept), and =--on-quit debug|quit= (default =quit=; =debug=
  enters aldo from ~(quit)~ / ~(exit)~ *before* the stack unwinds —
  continue quits, abort cancels). Each is mirrored by an AutoLISP
  variable — =*clal-on-error*=, =*clal-on-interrupt*=, =*clal-on-quit*= —
  and the interrupt / quit policies are re-read *live*, so ~(setq …)~
  overrides the CLI at runtime.
- *Debugger UI selection*: =--debugger-ui tui|ncurses|aldb= is the per-run
  override of the persisted =default-user-interface= aldo setting
  (=aldo.conf= is now consulted at launch); =--aldb-listen [HOST:]PORT= /
  =--aldb-stdio= configure the aldb (Emacs) channel and imply
  =--debugger-ui aldb= (the aldb RPC transport itself is still pending —
  selecting it fails with a clear message). These REPLACE the former
  =--aldo-user-interface= / =--aldb-listening-address= /
  =--aldb-listening-port= spellings (no aliases kept).

** Exit-status channel (portable pass/fail for batch scripts)

- ~(autolisp-set-status N)~ records an integer process exit status;
  ~(autolisp-status)~ reads it back (0 when never set). The name and
  integer semantics match the ~autolisp-set-status~ alfe injects into a
  driven AutoCAD / BricsCAD session, so one ~C:MAIN~ reports pass/fail

- ~(quit [status])~ / ~(exit [status])~ take an OPTIONAL integer: ~(quit

- These are clautolisp extensions: silent under ~--clautolisp~ / ~--lax~,
  and flagged with a non-fatal out-of-dialect WARNING under ~--strict~ /

  See ~issues/closed/autolisp-set-status-and-quit-status.issue~.

  (nil-returning placeholders) under every documented identifier.
  Calling a stub returns nil; ~(boundp 'X)~ is ~T~. Real impls track

  ~(vla-getboundingbox obj 'll 'ur)~: the two quoted output symbols

  entry — ~(entnext (cdr (assoc -2 (tblsearch "BLOCK" n))))~ walks the
  definition — and ~entget~ on a symbol-table record's ename (from
  ~tblobjname~) returns the record's group-code view, ~(-1 . ename)~
  head and ~-2~ included for blocks.
- The mock host grew a *drawing-command engine*: ~(command ...)~ still
  records and echoes every call, and now EXECUTES the model-only
  drawing commands the SCHMS corpus draws with — ~LINE~ (with
  ~_Close~), ~CIRCLE~, ~TEXT~ (with the ~_Justify~ options, decimal-
  degree rotation input stored as radians), ~DONUT~ (the vendors'
  closed two-arc constant-width LWPOLYLINE) and ~SOLID~ — creating
  real entities on the current layer that ~entlast~ / ~entnext~ /
  reactors see. Unknown commands and malformed input stay record-only.
  ~entlast~ now also skips subentities (ATTRIB / VERTEX / SEQEND), so
  ~(entlast)~ after an attribute-bearing insert names the INSERT, as
  the vendors do.

  do wherever a command prompts for object selection — the classic
  ~(command "._erase" ss "")~ idiom. The live set passes through to
  the host un-normalized, and the command engine grew the editing
  commands that consume object selection: ~ERASE~ (the subentity run
  goes too), ~MOVE~ and ~COPY~ (selection, base point, second point),
  each also accepting entity-handle input and the ~_Last~ option.
- ~ROTATE~ (selection, base point, angle in command angular units) and
  *~-BLOCK~* (name, base point, selection: registers the definition
  and absorbs the selected entities, translated so the base point
  becomes the definition origin — they leave model space, the vendor
  contract; a same-name definition is redefined) complete the engine's
  block-factory path.
- Geometric transforms (translate / rotate — Move, Copy, -BLOCK
  absorption, the command ~ROTATE~) and ~GetBoundingBox~ now apply to
  *every* occurrence of a point group, not just the first: a
  LWPOLYLINE (e.g. a DONUT) carries one 10 group per vertex, and
  transforming only the first corrupted its geometry — visibly, the
  bas/haut side discrimination of an inserted block. Point arity is
  preserved (2D vertices stay 2D).
- ~GetBoundingBox~ extends a text entity's box by its height in the
  direction the *vertical justification* dictates: a top-anchored
  (~_TL~/~_TC~/~_TR~) TEXT grows downward from its anchor, a
  baseline / bottom one upward, a middle one both ways (MTEXT: top
  attachment). Getting this wrong flipped topological above/below
  readings of ~_TL~ labels — the SCHMS côté BAS check. Command-name resolution honours that a leading
  ~-~ is *not* a generic modifier: ~-FOO~ is a distinct,
  explicitly-defined console-form command, so each dash form is
  registered explicitly (~-BLOCK~ today; on this TUI-only host the
  dialog spelling ~BLOCK~ projects onto the same console grammar);
  only the ~.~ and ~_~ prefixes are stripped as modifiers.
- ~acad_strlsort~ now really sorts: it returns a *new* list of the
  input strings in ascending, case-sensitive, ordinal order (upper
  before lower; accented / non-ASCII letters after the ASCII range),
  leaving the input list untouched and preserving duplicates. It was
  a nil-returning stub before. Invalid input (a non-list, an improper
  list, any non-string element) and a list longer than the ~MAXSORT~
  system variable both return nil, matching the Express Tools failure
  modes. See ~issues/closed/acad-strlsort-returns-nil.issue~.

** Other AutoLISP semantics matches

- ~command~ / ~command-s~ are real special forms routed through the
  Host Abstraction Layer: arguments evaluate, values normalize to
  command-line token strings (points as ~"X,Y[,Z]"~, ~""~ = RETURN,
  ~"\\"~ = PAUSE — the predefined ~pause~ variable is bound), and
  the sequence lands on the host command channel; MockHost records
  it and returns nil. ~vl-cmdf~ shares the routing and returns T on
  success. See the user manual § /Host backend/.
- ~(quit)~ and ~(exit)~ are catchable by ~VL-CATCH-ALL-APPLY~ — the
  vendor surface, needed by test frameworks like test-unitaire.lsp.
- Source-level ~'NIL~ normalises to CL nil so ~(a b c . NIL)~ is a
  proper list (REVERSE / LENGTH / MAPCAR etc. accept it).
- Reader accepts ~"42."~, ~"5."~, ~".5"~ as reals (vendor semantics,
  distinct from CL).
- Float printer emits ~"3.14"~ / ~"42.0"~ / ~"1.0e20"~ — no CL
  double-float marker.
- Relational operators ~<~, ~<=~, ~>~, ~>=~ fold non-numeric args
  (including nil) to nil — matches AutoLISP loop-guard idioms.
- ~(substr s start 0)~ returns ~""~.
- Locale-insensitive numeric I/O (period decimal separator regardless
  of ~LC_NUMERIC~ / ~DIMDSEP~).
- ~vl-file-systime~ returns *eight* elements — year, month, day of
  week, day of month, hours, minutes, seconds, milliseconds — matching
  every engine probed (AutoCAD 2022, BricsCAD V25 and V26) rather than
  the seven both vendors' reference pages state. The milliseconds
  field is currently always 0: ~CL:FILE-WRITE-DATE~ is defined in whole
  seconds. Day of week is 1..6 for Monday..Saturday everywhere; Sunday
  is the one value the vendor documentation never pins down, so it is
  dialect dependent — 0 under ~clautolisp~ / ~strict~ / ~autocad-*~
  (the POSIX ~struct tm~ completion, which is also what AutoCAD's
  runtime returns) and 7 under ~bricscad-v25~ / ~bricscad-v26~.
  ~(mod day-of-week 7)~ normalises every engine and dialect to the
  POSIX numbering, since ~(mod 0 7)~ and ~(mod 7 7)~ are both 0 and
  Monday..Saturday pass through unchanged. See the AutoLISP Spec entry
  § /VL-FILE-SYSTIME/ for the evidence.

* alfe — AutoLisp FrontEnd (=autolisp-front-end/documentation/alfe-user-manual.org=)

alfe is the multi-backend driver: it speaks the AutoLISP CLI surface,
resolves a backend (in-process clautolisp, or a CAD-host bridge via
file or COM), and forwards the workload.

** Backends (autolisp-front-end/documentation/alfe-user-manual.org § /Backends/)

- ~--clautolisp~ (default) — drive the in-process clautolisp engine.
  ~--host cador|nihil~ selects that engine's HAL backend: ~cador~ (the
  headless CAD core, default) or ~nihil~ (no CAD; operations signal
  ~:host-not-supported~). Honoured under ~--clautolisp~ only — under
  ~--autocad~ / ~--bricscad~ the real CAD is the host. (~mock~ = alias of
  cador; ~null~ / ~none~ = aliases of nihil.)
- ~--bricscad~ — drive a BricsCAD process via the file-protocol
  bridge (BricsCAD V26 / macOS). Output a script directs to a file it
  opened — ~(princ s f)~, ~(print s f)~, ~(prin1 s f)~ on a descriptor
  from ~(open path "w")~ — now lands in that file instead of leaking
  onto the captured stdout channel.
- ~--bricscad~ startup is robust to a corrupt per-user ~default.cui~:
  before launching, alfe quarantines an unreadable CUI (renames it
  aside so BricsCAD regenerates a fresh one) instead of letting the
  "CUI File Error / invalid document structure" modal stall a headless
  run. Opt out with ~$ALFE_NO_CUI_REPAIR~.
- ~--bricscad --mode batch~ on MS-Windows now launches BricsCAD with its
  main frame window *hidden*: alfe passes the BricsCAD ~/Automation~
  startup switch alongside the direct ~/b run.scr~ command. ~/Automation~
  is a BricsCAD executable switch (not COM) and does *not* select alfe's
  COM ~--mode automation~ backend — the file-protocol still drives the
  run, just without a visible window. Windows only; the macOS/Linux batch
  command is unchanged. See ~alfe-bricscad-batch-hidden-ui~.
- ~--autocad~ — drive an AutoCAD process (Windows + macOS lanes). The
  protocol stdout/stderr the CAD-side runtime writes is now decoded with
  the robust ~:auto~ cascade, not accoreconsole's console ~:utf-16le~ —
  the runtime writes those files in UTF-8/ASCII, so forcing UTF-16LE had
  turned captured output into mojibake (an explicit ~-Econsole~ /
  ~-Ecadstdio~ still forces a codec; the console *pipe* stays UTF-16LE).
- ~-Esource ENC~ on a CAD backend now decodes a codepage source and
  hands the CAD a UTF-8-with-BOM copy to ~(load)~. A CAD ~(load)~ has no
  encoding argument — it reads a BOM'd Unicode file, else the read-only
  host ~SYSCODEPAGE~ (macOS = Mac Roman) — so a raw cp1252 ~.lsp~ used to
  load with the wrong characters (a loaded ~é~ came back as ~È~, and
  ~(= (chr 233) loaded-é)~ was ~nil~). alfe now transcodes (via babel)
  and stages UTF-8+BOM, so the loaded character equals ~(chr N)~ on every
  platform. Confirmed on real BricsCAD V26.
- ~--echo~ — a test backend that logs without executing.
- On MS-Windows, ~--bricscad~ and ~--autocad~ now discover installed
  BricsCAD / AutoCAD binaries from the standard ~Program Files~ roots
  by default; ~BRICSCAD_EXE~, ~AUTOCAD_EXE~ and
  ~AUTOCAD_ACCORECONSOLE~ still override discovery explicitly.
- The CAD subprocess console I/O is decoded robustly: accoreconsole on
  a non-UTF-8 Windows writes UTF-16LE, which used to crash AutoCAD
  bootstrap with a UTF-8 decoding error. The channel drain now
  auto-detects UTF-16LE / UTF-8 (Latin-1 fallback, never signals), and
  the accoreconsole pipe reads with a total decoder, overridable via
  ~ALFE_AUTOCAD_CONSOLE_ENCODING~ or the per-situation ~-Econsole~ /
  ~-Ecadstdio~ options (see § /Encoding/ below).
- ~--autocad~ discovery now prefers real AutoCAD over the read-only
  DWG TrueView viewer (both ship ~accoreconsole.exe~; only AutoCAD can
  mutate entities), so a host with both no longer picks the viewer.
- ~--mode~ and ~--dwg~ are now forwarded correctly into CAD backend
  startup, so ~alfe --autocad --mode batch --dwg file.dwg ...~ no
  longer falls back silently to ~:auto~ / automation mode.
- ~alfe --autocad --mode batch~ now falls back to
  ~AUTOLISP_DWG~ or a shipped ~acadiso.dwt~ / ~acad.dwt~ template
  next to the discovered AutoCAD install, instead of requiring an
  explicit ~--dwg~ on every invocation.
- AutoCAD batch bootstrap now reports the child ~accoreconsole~
  process exit code and console diagnostics immediately when the CAD
  process dies before publishing ~READY~, instead of timing out with a
  generic ~READY-TIMEOUT~.

** CAD selection (alfe-user-manual § /Selecting a specific CAD install/)

- ~--list-cad-programs~ scans the host and prints every installed CAD
  with its canonical denotation (~acad-2026~, ~accoreconsole-2022~,
  ~bricscad-v25-fr_FR~, ~clautolisp~, …).
- ~--cad DENOTATION~ selects a specific install: exact, or bare/partial
  → the latest version; the virtual ~autocad~ resolves to ~acad~ or
  ~accoreconsole~ per ~--mode~. Among same-version BricsCAD locales the
  host language preference (macOS ~AppleLanguages~; ~LANG~ / ~LC_*~)
  breaks the tie.

** Encoding (alfe-user-manual § /Encoding/)

- Per-*situation* encoding CLI: ~-E<situation>[-<dir>] ENC~ /
  ~--<situation>-encoding ENC~ for ~source~ / ~file~ / ~console~ /
  ~cadstdio~ / ~log~ / ~terminal~, plus a bare ~-E ENC~ that sets them
  all. This replaces the previous ~-e~ / ~-E~ flags. ~-Eterminal~ now
  reconfigures alfe's own stdout/stderr/stdin; ~-Esource~ is forwarded
  into the CAD's native ~(load)~; ~-Econsole~ / ~-Ecadstdio~ drive the
  console/pipe decode (a product-fixed situation such as accoreconsole's
  UTF-16LE console warns that the option is ignored and keeps the
  product value).
- ~--list-situations~ prints the encoding situations and their
  directions; under a backend flag it prints that backend's per-situation
  default provenance (settable / product-fixed / LISPSYS / …).

** Modes

- ~--mode auto~ (default), ~--mode batch~, ~--mode automation~.
  See § /Backend invocation/ for the file-protocol handshake.

** Output line discipline (CAD backends)

- On the CAD backends, ~princ~ and ~prin1~ no longer terminate a line:
  consecutive output primitives in one form concatenate, and only
  ~terpri~, ~print~'s framing, or an explicit ~\n~ break the line — matching
  the clautolisp REPL and real AutoLISP. ~(terpri)~ now routes its break
  through the captured output too. (Before, each ~princ~/~prin1~ emitted a
  spurious trailing newline; confirmed fixed on real BricsCAD V26.)

- On the CAD backends, a top-level ~(load X)~ now evaluates its argument:
  ~(load p)~ and ~(load (strcat dir "f.lsp"))~ work, not only string
  literals. (Before, a non-literal argument reached ~findfile~ unevaluated
  and failed with ~bad argument type~; confirmed fixed on real BricsCAD V26.)

** Request timeout (alfe-user-manual § /Troubleshooting/)

- ~--timeout~ / ~$AUTOLISP_WAIT_SECS~ now reaches the CAD backends'
  per-request wait (previously parsed but ignored there). It is
  *RUNNING-aware*: by default the timeout bounds only the
  ~READY N~ → ~RUNNING N~ handshake, and once the engine acknowledges a
  request and its process is alive a long ~(eval …)~ is kept running
  rather than aborted on wall-clock; a dead engine still aborts
  promptly. An explicit ~--timeout N~ is a hard cap that restricts as
  well as extends (~--timeout 1~ aborts, ~--timeout 600~ grants ten
  minutes).

** Diagnostics under ~--verbose~ / ~--debug~

- Both flags now emit progressive diagnostics through every
  backend's lifecycle (workdir, argv, BOOTSTRAP timing, status-file
  polling). The old "single error line" failure mode is gone.

- A CAD launcher that dies before the engine is ready now fails *fast
  and specifically*. Previously alfe waited out the whole READY timeout
  and reported a bare ~READY-TIMEOUT~ with an empty status file, while
  the launcher's exit code and stderr — the actual diagnosis — were
  discarded. A launcher exiting NON-ZERO now aborts the wait at once
  with ~LAUNCHER-FAILED~ and reports its exit code and stderr. A
  launcher exiting 0 is *not* an error: in ~--mode automation~ it is a
  driver that has done its job (~osascript~ once it has typed,
  ~cscript~ once it has dispatched the COM command) and the CAD
  publishes READY afterwards, so the wait continues as before.

- macOS ~--mode automation~: the emitted AppleScript launcher could
  never run. It used ~running~ — a reserved AppleScript property term —
  as a variable, and addressed the app as ~"BricsCAD"~ while the
  installed bundle is e.g. ~BricsCAD V26.app~. It now launches and
  activates the real bundle in one step (~open -a~ with the bundle
  derived from the discovered binary), waits longer for a cold start
  (8 s, override with ~$ALFE_BRICSCAD_STARTUP_DELAY~), and the
  placeholder substitution no longer applies VBScript quote-doubling to
  an AppleScript template. Whether the keystroke mechanism can work on
  a headless CI runner at all (it needs an interactive session and
  Accessibility permission) is still open — but it now says so instead
  of hanging.

- ~--print-command~ prints the CAD command line alfe *would* launch,
  and launches nothing. It stages the workdir for real (runtime and
  bootstrap LSP, ~run-common.lsp~, ~run.scr~ or the VBScript /
  AppleScript bridge), then writes exactly one shell-ready line to
  stdout — every argument quoted for the host shell — so
  ~cmd=$(alfe --bricscad --print-command …)~ works. The workdir is
  erased on the way out unless ~--keep-workdir~ is given. CAD backends
  only: under ~--clautolisp~ there is no external command line, and
  alfe exits 2 with a usage error. Running the printed command by hand
  boots the CAD against the staged workdir but stops at ~READY~, since
  nothing drives alfe's side of the file-IPC protocol — it is a
  launch-time debugging aid (switches, licensing, profile, startup
  modals), not a substitute for a run. Distinct from ~--dry-run~,
  which resolves nothing, touches no disk, and prints only the plan.

** Image-introspection variables

  § /The *AUTOLISP-…* globals/ table.

** File-protocol reliability (Windows)

- Reading a status/protocol channel no longer aborts on the transient
  Windows failure that the non-atomic delete-target+rename replace
  window can raise: an open landing mid-replace could fail with
  ACCESS-DENIED (a FILE-ERROR), or a read be interrupted (a
  STREAM-ERROR), and that escaped as an unhandled error (intermittent
  ~test:alfe:windows~ on the CAD control-sentinel test). Such transients
  are now retried briefly and, failing that, read as empty — the same
  "not published yet, try again next tick" contract already used for the
  delete-gap. Dormant on POSIX (atomic rename never triggers it).

** On release-1.8.41, 1.8.42 and 1.8.43

All three tags exist and publish NOTHING: no pipeline produced the
artefacts, and no GitLab Release was created for any of them. A tag never
moves and is never deleted, so the three stay as the record of the
attempts. *1.8.46 is the first published release of the series since
1.8.0.*

The third one is the instructive failure. Its pipeline went GREEN and
still produced nothing: =collect:release= was SKIPPED, because it
required =release:linux:arm32=, whose only rule is =when: manual= — an
experimental qemu lane that never starts on a tag. A needs entry that
cannot be satisfied makes GitLab skip the job rather than fail it, so
nothing was red anywhere. Fixed in 1.8.46, together with a check that
refuses that combination.

Each attempt failed on a different fault, and each fault is fixed in the
release that follows it — which is why they had to be separate tags
rather than one retried:

- *1.8.41* — stale =accoreconsole= processes held a file under =dist/=
  open, so the runner's =git clean= failed and every Windows job died
  before its own script ran; and libredwg's parallel build exhausted the
  machine's memory. Fixed in 1.8.42.
- *1.8.42* — =build:alfe:windows= could not upload a ~13 MB artefact
  (the connection was cut mid-POST), and that job was release-blocking.
  The artefact had no consumer at all, so 1.8.43 stops producing it.

- *1.8.43* — =collect:release= required a job that never runs, so it was
  skipped and the pipeline was green with nothing to show. Fixed in
  1.8.46.

The deeper fix arrived with 1.8.43, and it is the one that matters beyond
these three: *a release is no longer hostage to an absent machine*. On a
release tag a platform's jobs run and are mandatory unless the person
cutting the release declares the machine absent
(=SKIP_WINDOWS_RELEASE=1= / =SKIP_MACOS_RELEASE=1=), in which case the
release ships without that platform's products instead of waiting.

The first attempt at that read runner availability automatically, from
=detect:runners=. It could not work: GitLab evaluates =rules:= at
pipeline creation, before any job has run, so a variable published as a
dotenv artefact does not exist yet — and the jobs were silently not
created at all. Declaring the absence explicitly is less clever and
cannot fail that way.

** What release-1.8.46 actually shipped

1.8.46 is published, and it is the first tag of the series to publish
anything at all — including the two Windows =.zip= files, the platform
the three previous attempts never reached. It shipped *14 of the 17*
artefacts. Three are missing, for two independent reasons, both fixed in
1.8.47:

- =clautolisp-1.8.46-all.zip= was never written. The =-all= union is
  archived from *inside* the staging tree, and the CI passes a RELATIVE
  =COLLECT_OUT=dist/combined=, so =zip= resolved its output path against
  that staging tree instead. The log still said "wrote ... all.zip".
  =collect-artefacts= now resolves its paths to absolute before packing
  anything. The check that exists to guard the artefact set had been
  passing over this bug for one reason: it invoked the recipe with
  ABSOLUTE paths. It now uses relative ones, the way the CI does, and
  fails without the fix.

- =clautolisp-1.8.46-binaries-linux-arm32.tar.bz2= and its =libraries=
  counterpart do not exist. =release:linux:arm32= went green in 35
  seconds having built nothing: its optional CCL install was guarded by
  =exit 0=, and GitLab concatenates =before_script= and =script= into a
  single shell — so the guard ended the whole job, ended it
  successfully, and the runner uploaded an empty =dist/=.

The second failure is the one worth generalising, because *green plus
empty* is indistinguishable from *green plus complete* to everything
downstream. Every per-target lane now ends with =make
verify-release-artefacts=, which fails unless this target's two artefacts
exist and are not husks; =make check-release= enforces both that every
lane runs it and that no =before_script= contains an =exit=.

** What a release publishes

Every release publishes, per target, a =binaries-<os>-<arch>= and a
=libraries-<os>-<arch>= artefact — =.tar.bz2= everywhere, =.zip= for
Windows, whose package has its own layout — plus the merged
multi-platform =binaries= / =libraries= tarballs, the documentation
tarball, and the sources as both =.tar.bz2= and =.zip=.

=clautolisp-<version>-all.tar.bz2= and =clautolisp-<version>-all.zip=
are the *unpacked union* of all of the above: one archive to extract and
everything is in place at once, rather than an archive of archives. The
two containers ship the same tree, the =.zip= being there for Windows
users.

The sources sit under =src/clautolisp-<version>/= — in their own
artefacts and inside =-all= alike (pjb, 2026-08-18; before that they
were at the top, as =clautolisp-<version>/=). Every other artefact
unpacks into =$PREFIX=, so in the union a bare =clautolisp-<version>/=
stood as a sibling of =bin/=, =lib/= and =share/= with nothing to mark
it as a source tree. =src/= marks it, and unpacking =-all= over a
prefix still does not scatter sources into it.

The published release links now *download*. A GitLab release attaches
its archives from the collect job, and those links used the artefact
*browsing* URL, which serves HTML: both forms answer =200=, so a script
following one wrote 40 KB of HTML to disk under the archive's name and
failed later, at extraction, complaining about the archive format rather
than about the link. The releases of 1.8.47 and 1.8.49 have been
repaired in place, and the artefacts they point at no longer expire — a
release is permanent, so its assets must be too, and a 30-day expiry
turned every release older than a month into dead links while the page
went on looking published.

The artefacts carry no macOS metadata. Packing on macOS used to store
extended attributes as AppleDouble =._NAME= members, which reached the
darwin artefact and, from there, =-all.zip= — where they extracted as
junk beside every directory, while the =.tar.bz2= of the same union was
clean. Two containers of one union now unpack to the same tree, which is
the property =-all= exists to provide.

** Installing never builds as root

Installing is two halves, split so that no compiler ever runs with
root privileges — a build run as root leaves root-owned fasls, cmake
trees and PDFs inside the working checkout that you can no longer
overwrite:

1. *stage* (unprivileged): ~make stage~ builds each artefact kind and
   lays it out under ~dist/stage/<kind>/~ exactly as it must appear
   below ~$PREFIX~. Split as ~stage-programs~, ~stage-libraries~,
   ~stage-documentation~.
2. *install* (privileged): ~sudo make install~ copies those trees into
   ~$DESTDIR$PREFIX~ and does nothing else. Split the same way:
   ~install-programs~, ~install-libraries~, ~install-documentation~.

~sudo make install~ is still a valid one-liner: when the install half
finds itself running as root under ~sudo~ it re-runs the staging half
as ~$SUDO_USER~ first. Set ~STAGE~ to relocate the staging area.

The global ~make install~ now covers all three phases, documentation
included. A host without the documentation toolchain (Emacs +
TeX/xelatex + makeinfo) installs the other two explicitly:
~sudo make install-programs install-libraries~.

The release artefacts are packaged from the same staged trees
(~release-libraries~ and ~release-documentation~ tar up
~dist/stage/libraries~ and ~dist/stage/documentation~), so what you
install and what a release ships cannot drift apart. The one
exception is the binaries artefact: it ships a ~bin/~ of dispatch
wrappers over ~libexec/clautolisp/binaries/<os>/<arch>/~ so CI can
union several platforms into one archive, whereas ~install-programs~
installs this host's binaries directly into ~bin/~ along with the
harnesses and helpers no end-user tarball carries.

** Which build am I running?

Every staged tree carries a provenance manifest, installed as

: $PREFIX/share/doc/clautolisp/manifest-<phase>.txt

one per phase (=programs=, =libraries=, =documentation=), because the
phases can be built and installed separately. Each names the repository
the code came from and the release tag it was built from — or, when the build is not exactly on a
release, how far past the last one it is — plus the commit, the branch,
whether the build tree was clean, the version of every shipped program,
and the host it was built on:

#+BEGIN_EXAMPLE
phase:        programs
origin:       git@gitlab.com:ogamita/clautolisp.git
release:      release-1.6.11
describe:     release-1.6.11
commit:       623356e109605579f3578cb3d92f0475595a8917
commit-date:  2026-07-25T13:20:49+02:00
ref:          master
tree:         clean
programs:     clautolisp 1.6.11, alfe 1.6.0, read-autolisp 1.6.0
built:        2026-07-25T16:49:43Z on darwin/arm64
#+END_EXAMPLE

The release artefacts carry the same file, and the source tarball
carries =manifest-sources.txt= at its root — so a build made from an
unpacked tarball, with no git checkout to interrogate, still reports the
commit it descends from. ~RELEASE_NOTES.org~ (this file, also installed
under =share/doc/clautolisp/=) tells you what a release *contains*; the
manifest tells you *which build you have*.

** Libraries (=make install-libraries=)

Besides the executables, the libraries phase installs clautolisp as an
ASDF-loadable Common Lisp library:

| What                       | Where                                           |
|----------------------------+-------------------------------------------------|
| ASDF systems (.lisp, .asd) | =$PREFIX/share/common-lisp/source/clautolisp/=  |
| system index symlink       | =$PREFIX/share/common-lisp/systems/clautolisp.asd= |
| ASDF source-registry fragment | =$PREFIX/etc/common-lisp/source-registry.conf.d/50-clautolisp.conf= |
| native DWG codec libraries | =$PREFIX/lib/clautolisp/<os>/<arch>/=           |
| libredwg public header     | =$PREFIX/include/clautolisp/dwg.h=              |
| drawing spec + libredwg licence | =$PREFIX/share/doc/clautolisp/=            |

~make install-libraries~ installs exactly what the
=clautolisp-<ver>-libraries-<os>-<arch>.tar.bz2= artefact packages —
same files, same paths — so installing from source and unpacking the
release tarball are interchangeable.

~make -C clautolisp install~ now runs this phase too, so the
subproject-level install produces the same complete tree the top-level
~make install~ does: programs + Lisp sources + ASDF systems + native
libraries + documentation. Previously it installed only programs and
documentation, and a full installation could be obtained only from the
repository root or by unpacking a release tarball.

A checkout without the LibreDWG submodule no longer fails the phase.
Only the ~clautolisp/drawing-dwg~ system needs the native DWG codec, so
when it has not been built the phase installs everything else, prints
what it skipped, and says how to add it later:

#+BEGIN_EXAMPLE
git submodule update --init clautolisp/third-party/libredwg
make -C clautolisp build-libredwg install-libraries
#+END_EXAMPLE

Release packaging keeps the old hard failure — ~make release-libraries~
sets ~REQUIRE_NATIVE_LIBRARIES=1~ — so a published libraries tarball can
never silently ship without its codec.

With ~$PREFIX/share/common-lisp/~ on ASDF's source-registry (the
default system registry already covers ~/opt/local~, ~/usr/local~ and
~/usr~), ~(asdf:load-system "clautolisp")~ works from any Lisp image —
and the ~drawing-dwg~ shim finds the installed native libraries by
deriving ~$PREFIX~ from its own installed source directory. For a
~$PREFIX~ outside that default set, the phase installs a
~source-registry.conf.d~ fragment for exactly that case:

#+BEGIN_EXAMPLE
$PREFIX/etc/common-lisp/source-registry.conf.d/50-clautolisp.conf
#+END_EXAMPLE

It registers ~$PREFIX/share/common-lisp/source/~ by a path relative to
its own directory (ASDF's ~:here~), so the installed tree stays
relocatable and the staged tree carries no ~$PREFIX~ inside it. ASDF
reads it once ~$PREFIX/etc~ is on ~XDG_CONFIG_DIRS~ — already true for
~/etc~; for the ~/opt/local~ default:

#+BEGIN_EXAMPLE
export XDG_CONFIG_DIRS=/opt/local/etc:${XDG_CONFIG_DIRS:-/etc/xdg}
#+END_EXAMPLE

Note that a user configuration saying
~:ignore-inherited-configuration~ — e.g. a one-line
~~/.config/common-lisp/source-registry.conf~ — discards the defaults
*and* every system-level fragment, this one included, and with them
everything installed under ~$PREFIX~. That is the configuration's
prerogative; the way back in is a ~conf.d~ file of one's own:

#+BEGIN_EXAMPLE
;; ~/.config/common-lisp/source-registry.conf.d/50-local.conf
(:tree "/opt/local/share/common-lisp/source/")
#+END_EXAMPLE

*** One .asd file, many systems

The whole library is *two* ~.asd~ files, which is expected, not a
truncated install: ~clautolisp.asd~ defines the primary system
~clautolisp~ *and* all 44 of its subsystems —
~clautolisp/autolisp-reader~, ~clautolisp/autolisp-runtime~,
~clautolisp/drawing~, ~clautolisp/drawing-dwg~,
~clautolisp/read-autolisp~, the ~/tests~ systems, … ASDF calls these
*secondary systems*: for a name of the form ~primary/secondary~ it
searches the registry for the *primary* name only, loads
~clautolisp.asd~, and looks the secondary system up inside it. So
~(asdf:load-system "clautolisp/drawing-dwg")~ needs no
~clautolisp-drawing-dwg.asd~ anywhere — and there is deliberately no
per-subsystem ~.asd~ to install.

The whole source tree ships as the library: every tracked ~.lisp~ and
~.asd~ (242 + 2 at 1.6.11), not a curated "public" subset. Drawing a
library / non-library line would be arbitrary — the tools reuse the
same subsystems callers do (~read-autolisp~ is
~clautolisp/read-autolisp~) — and clautolisp is AGPL, so the sources
travel with it anyway.

The second file, ~autolisp-debug-ui-tui-charms/clautolisp-charms.asd~,
is the exception that proves the rule: it defines
~clautolisp/autolisp-debug-ui-tui-charms~, whose primary name is
~clautolisp~, so ASDF will never find it by name from any registry. It
is kept out of ~clautolisp.asd~ on purpose — it needs cl-charms /
libncurses and a real terminal, which must never be required to build
or test clautolisp — and is loaded explicitly:

#+BEGIN_EXAMPLE
(asdf:load-asd #p"$PREFIX/share/common-lisp/source/clautolisp/autolisp-debug-ui-tui-charms/clautolisp-charms.asd")
(asdf:load-system "clautolisp/autolisp-debug-ui-tui-charms")
#+END_EXAMPLE
