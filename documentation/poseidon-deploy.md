# Publishing the AutoLISP spec to poseidon

The GitLab CI `deploy:documentation` job publishes the prebuilt HTML manual
produced by `release:documentation` to the poseidon web site:

    http://poseidon.informatimago.com/ogamita/autolisp-spec/

## Pipeline

1. `release:documentation` (stage `release`, runs on thalassa) builds the
   paged HTML/Info/PDF and packages `dist/clautolisp-<ver>-documentation.tar.bz2`.
   That tarball ships the browsable HTML manual at
   `share/doc/autolisp-spec/html/` (index.html + symbols.html + per-section
   pages).
2. `deploy:documentation` (stage `deploy`, runs on the poseidon group
   runner) pulls that artefact via `needs:`, unpacks it, and `rsync`s
   `share/doc/autolisp-spec/html/` over SSH onto the poseidon web root.
   It runs on a version tag (`v*` / `clautolisp-v*`) or manually.

These HTML pages are **build output** — "object files" of the documentation
job. They are deployed here, never committed. The poseidon web site is its
own git repo whose `.gitignore` excludes `ogamita/autolisp-spec/`.

## Deploy mechanism (least privilege)

Everything published under `/var/www/poseidon/public_html/ogamita` -- the
spec manual (`deploy:documentation`) and the release sets (`collect:release`,
`scripts/mirror-release-to-poseidon.sh`) -- is sent to ONE account,
`release-ogamita` (pjb, 2026-10-24). It owns the tree, group `www-data`:
directories 755, files 644, release archives 444 (a published release is
read-only). Only senders ON poseidon have a key there:

- the CI jobs: a job SSHes back to poseidon's own sshd with the private key
  held in the `DEPLOY_SSH_PRIVATE_KEY` CI/CD variable (the Docker runner runs
  as root, the shell runner as `runners`; both reach it through
  `poseidon.informatimago.com`);
- `runners` and `claude`, each with its own `~/.ssh/release-ogamita` key
  (`scripts/deploy-release-to-poseidon.sh --from DIR` uses it, no sudo).

Each `authorized_keys` entry is an **rrsync forced command**:

    command="/usr/bin/rrsync /var/www/poseidon/public_html/ogamita",restrict ssh-ed25519 AAAA...

so a key can ONLY `rsync` inside that tree -- no shell, no other path, no
port/agent/X11 forwarding. rrsync chroots the session there, so senders
address paths relative to it: `autolisp-spec/`, `clautolisp/releases/<ver>/`.

The index pages of the releases area are generated by the SENDER
(`gen-release-index.py --version` / `--root-index`, the version list read with
`rsync --list-only`): the account runs no command of its own.

## Setup

Run the helper on poseidon as root, naming the senders' PUBLIC keys -- it
creates the account, writes one rrsync entry per key, and sets the tree's
owner and modes. It never reads or prints a private key:

    sudo env KEYS="<ci-key>.pub /home/claude/.ssh/release-ogamita.pub /home/runners/.ssh/release-ogamita.pub" \
        sh documentation/setup-deploy.sh

Register in **Settings > CI/CD > Variables** (File type, **protected +
masked**):

| Variable                 | Value                                               |
|--------------------------|-----------------------------------------------------|
| `DEPLOY_SSH_PRIVATE_KEY` | base64 (one line) of the CI key's private half      |
| `DEPLOY_KNOWN_HOSTS`     | base64 of `ssh-keyscan poseidon.informatimago.com`  |

> **Why base64?** A masked variable must be a single line with no
> whitespace; the jobs `base64 -d` it back (a File-type variable works too).

Protected variables reach only protected refs: `release-*` tags are
protected, so the release mirror runs there. To rotate the CI key: generate
a new pair, re-run the setup with its `.pub` in `KEYS`, then replace
`DEPLOY_SSH_PRIVATE_KEY` -- keeping the private half out of every log.

The former `clautolisp-deploy` account (the spec directory only) is retired:
its `authorized_keys` is empty since 2026-10-24.

## Home-page link / web site under git

The deployed pages are reached from the poseidon home page. The companion
helper `documentation/setup-poseidon-website.sh` (run once, as root) puts
the DocumentRoot under git, `.gitignore`s the CI-deployed
`ogamita/autolisp-spec/` pages (build output, not site source), and adds
the link to `/ogamita/autolisp-spec/` on the home page:

    sudo documentation/setup-poseidon-website.sh
