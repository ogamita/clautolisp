* Introduction

=alfe(1)= is the unified command-line front-end for AutoLISP. It
drives three backends behind a single command-line shape:

- =clautolisp= — an in-process AutoLISP evaluator that ships with
  alfe. No CAD required. The default backend.
- =bricscad= — BricsCAD V26+, via batch (=-b run.scr=) or COM
  /AppleScript automation. On MS-Windows, =--mode batch= launches
  BricsCAD with its main frame window hidden (the =/Automation=
  startup switch); this is just a hidden-UI batch run and does *not*
  select the COM =--mode automation= backend.
- =autocad= — AutoCAD 2026+, via =accoreconsole= batch or COM
  automation (MS-Windows only).

The same =-x EXPR=, =-l FILE=, =--dialect NAME= and =--host MODE=
options work against every backend. Programs written for alfe run
unchanged whether you point them at the local clautolisp engine
or at a real CAD session.

* Installation

The build target produces two binaries: =alfe-sbcl= (preferred,
faster startup) and =alfe-ccl= (Clozure CL backup, when SBCL is
unavailable). The =install= rule places them under
=$(PREFIX)/bin/= along with a wrapper =alfe= that resolves to one
or the other:

#+begin_src sh
cd autolisp-front-end
make build
sudo make install PREFIX=/opt/local
#+end_src

After install:

#+begin_src sh
alfe --help                    # full option reference
alfe -x "(print (+ 1 2))"      # one-shot eval, prints "3" then exits
alfe -x "(+ 1 2)"              # silent — see "Action output semantics" below
alfe -l script.lsp             # load a file, default backend
alfe                           # interactive REPL, default backend
#+end_src

The =--clautolisp= / =--bricscad= / =--autocad= flags select a
specific backend; absent a flag, the in-process clautolisp engine
is used (see [[#backend-selection][Backend selection]]).

* Backend selection
:PROPERTIES:
:CUSTOM_ID: backend-selection
:END:

When no backend flag is given, alfe defaults to the =clautolisp=
in-process engine. This is a change from the historical
auto-detection: CAD backends are now NEVER selected automatically
— they require an explicit =--autocad= / =--bricscad= flag (or
an environment override).

** Algorithm

#+begin_example
if --bricscad, --autocad or --clautolisp is explicit:
    use that backend
else if $ALFE_BACKEND_OVERRIDE is set:
    use that backend
else if $AUTOLISP_BACKEND is set:
    use that backend (legacy alias)
else:
    backend = clautolisp     ; default on every system
#+end_example

** Why not auto-detect?

A host with both BricsCAD and AutoCAD installed got
order-dependent results from the historical auto-detect (whichever
backend's =DETECT= method was probed first won). With the new
rule, =alfe= with no flags always means "talk to the in-process
clautolisp engine" — no probing, no surprises, no dependency on
CAD installation state.

** Pinning a default backend per shell

Users who want a CAD backend selected by default can set
=$ALFE_BACKEND_OVERRIDE= once in their shell init:

#+begin_src sh
# ~/.zshrc or ~/.bashrc
export ALFE_BACKEND_OVERRIDE=bricscad
#+end_src

Explicit flags still win — =alfe --clautolisp -x "(+ 1 2)"= runs
under clautolisp even with the override set.

** Selecting a specific CAD install

=--clautolisp= / =--bricscad= / =--autocad= pick the *latest* install
of a backend. When several versions or localisations are present and
you need a particular one, use =--cad DENOTATION=.

=alfe --list-cad-programs= scans the host and prints every installed
CAD with its canonical denotation:

#+begin_example
acad-2026                /Applications/Autodesk/AutoCAD 2026/…/MacOS/AutoCAD
accoreconsole-2026       /Applications/Autodesk/AutoCAD 2026/…/AcCoreConsole
bricscad-v26             /Applications/BricsCAD V26.app/Contents/MacOS/bricscad
clautolisp               (embedded in alfe)
#+end_example

Denotation grammar:

| Denotation                | Selects                                             |
|---------------------------+-----------------------------------------------------|
| =acad-2026=               | that exact AutoCAD (GUI =acad=)                     |
| =accoreconsole-2022=      | that exact =accoreconsole=                          |
| =bricscad-v25-fr_FR=      | that exact BricsCAD version + locale                |
| =bricscad-v25=            | V25 of any locale (host locale preference breaks ties) |
| =acad= / =bricscad=       | the latest of that kind                             |
| =autocad= / =autocad-2022= | =acad= or =accoreconsole= per =--mode= (batch → accoreconsole, else acad) |
| =clautolisp=              | the embedded engine                                 |

So =alfe --cad bricscad-v25-fr_FR -l script.lsp= runs a specific
BricsCAD, and =alfe --cad autocad-2022 --mode batch= selects
accoreconsole 2022. =--cad= sets the backend (a conflicting
=--autocad= / =--bricscad= on the same line is an error) and, for a
CAD, points that backend's discovery at the chosen executable. When
several BricsCAD locales of the same version are installed, the host
language preference (macOS =AppleLanguages=; Unix =LANG= / =LC_*=)
picks one.

* Dialect selection

The =--dialect NAME= option (and its =--strict= / =--autocad= /
=--bricscad= / =--clautolisp= shorthands) selects the AutoLISP
dialect descriptor the runtime uses: which reader knobs are on,
which encoding default applies, which special-case syntax is
accepted.

| Option         | Dialect        | Notes                                           |
|----------------+----------------+-------------------------------------------------|
| =--dialect strict= / =--strict= | =strict=       | Default. Portable AutoCAD ∩ BricsCAD subset.    |
| =--dialect autocad-2026= / =--autocad= | =autocad-2026= | AutoCAD 2026 surface. UTF-8 default encoding.   |
| =--dialect bricscad-v26= / =--bricscad= | =bricscad-v26= | BricsCAD V26. Lax reader, hex-float =atof=.     |
| =--dialect clautolisp= / =--clautolisp= | =clautolisp=   | Superset of strict + clautolisp extensions.     |

The dialect is independent of the backend — you can run
=alfe --clautolisp --dialect bricscad-v26 script.lsp= to evaluate
under the BricsCAD reader rules in the in-process engine, which
is useful for testing.

Whatever the dialect selected, all operators remain callable.
Out-of-dialect operators are eligible for a diagnostic warning at
use time (the warning machinery itself is tracked separately —
see =deferred-clautolisp-out-of-dialect-warnings.issue= in the project
issue tracker).

* Host selection

=--host MODE= picks the HAL (host abstraction layer) backend the
clautolisp engine talks to. Defaults to =mock= (a recording host
that consumes =--mock-input PATH= for =GETSTRING= /
=GETPOINT= prompts).

| Option        | Host                                           |
|---------------+------------------------------------------------|
| =--host mock= | MockHost (default). Drives prompts from a file or stdin. |
| =--host null= | NullHost. All host calls return nil immediately.        |

For the CAD backends the host is the CAD itself — =--host= has no
effect there.

* CAD engine control

Four options govern *how* a CAD engine is obtained and how much of the
bootstrap it runs. They apply to the CAD backends (=--bricscad=,
=--autocad=); the clautolisp backend ignores them, since it needs
neither a launch nor a workdir handshake.

| Option                        | Effect                                          |
|-------------------------------+-------------------------------------------------|
| =--backend attach\vert{}launch=      | Attach to an already-running CAD, or launch a fresh one. |
| =--workdir DIR=               | Override the exchange directory (default: =$AUTOLISP_WORKDIR=). |
| =--bootstrap-phase PHASE=     | Truncate the bootstrap at =marker=, =core=, =log= or =full=. |
| =--epure=                     | Enable the EPURE plugin hook (default: =$AUTOLISP_EPURE=). |

=--workdir= names the directory through which alfe and the CAD engine
exchange files — the file-IPC channel the CAD backends run on. Point it
somewhere you can read when you want to inspect that traffic; combine it
with =--keep-workdir= (or =$AUTOLISP_KEEP_WORKDIR=), which stops alfe
deleting the directory at the end of the run, since by default there is
nothing left to look at.

=--bootstrap-phase= truncates the engine-side bootstrap, which is how
you diagnose a CAD that never reaches =READY= — work *up* from =marker=
and the phase that stops working is the one at fault:

| Phase     | Behaviour                                                       |
|-----------+-----------------------------------------------------------------|
| =marker=  | Writes a startup marker and a status, nothing else. *Your actions are not executed* — this only proves the engine started and can write to the workdir. |
| =core=    | Executes actions with basic file I/O, but does *not* capture =print= / =princ= / =prompt= output. |
| =log=     | =core= plus the CAD-log setup (=LOGFILEMODE=, =LOGFILEPATH=, =LOGFILENAME=). |
| =full=    | The default: CAD log, capture of Lisp output, batch REPL under =-i=, and the remote protocol. |

Two consequences worth knowing before you use a truncated phase: under
=marker= a run that "succeeds" has not run your script at all, and under
=core= a script that prints its results looks silent because the capture
is not installed. =--interactive= requires =full= — combined with any
other phase, alfe exits with code =2=.

=--epure= turns on the EPURE plugin hook. Note that BricsCAD's EPURE
profile is not selected by this option — it requires its own explicit
launch options.

The three environment variables =$AUTOLISP_WORKDIR=,
=$AUTOLISP_BOOTSTRAP_PHASE= and =$AUTOLISP_EPURE= supply the defaults;
an explicit option always wins.

* Actions

alfe accepts an ordered queue of actions on the command line. The
queue runs in order then the engine terminates (or enters the
REPL with =-i=).

| Option              | Action                                          |
|---------------------+-------------------------------------------------|
| =-x EXPR= / =--eval EXPR= | Evaluate EXPR. Value is NOT auto-printed — wrap with =(print …)= if you want it back on stdout. See "Action output semantics" below. |
| =-l FILE= / =--load FILE= | Load and evaluate FILE.                         |
| =FILE.lsp= (positional)  | Equivalent to =-l FILE.lsp=.                    |
| =-i= / =--interactive=   | Enter REPL after the queue (same context). Auto-printing is enabled in the REPL only.      |
| =--quit=               | Force engine shutdown after the queue.          |
| =--dry-run=            | Print the resolved plan; don't run anything.    |
| =--print-command=      | Stage the workdir for real, print the CAD command line that would be launched, launch nothing. CAD backends only. |

Examples:

#+begin_src sh
alfe -x "(print (+ 1 2))"                # → 3
alfe -x "(+ 1 2)"                        # silent — value discarded
alfe -l prelude.lsp -x "(my-main)"       # load then call
alfe -l script.lsp -i                    # load then drop to REPL
alfe --bricscad -l ../scripts/draw.lsp   # run under BricsCAD
alfe --dry-run -l foo.lsp                # show the plan only
#+end_src

** Action output semantics

=-x EXPR=, =-l FILE= and =--main FN= are *batch* evaluations, not
REPL steps. The value an action produces is *not* echoed to alfe's
stdout — use an explicit printing primitive in the expression
(=(print …)=, =(princ …)=, =(prin1 …)=) when you want the value
to come back. This is uniform across the =--clautolisp=,
=--bricscad= and =--autocad= backends.

The interactive REPL (=-i= / =--interactive=) is the only context
where values are auto-printed: there, each top-level form's value
is read, evaluated and printed (read-eval-print loop). =-x= and
=-l= actions issued alongside =-i= remain silent-by-default; only
forms typed AT the REPL prompt print their values.

If you want a one-line shorthand for "evaluate and print", define a
helper in your init file:

#+begin_src lisp
(defun ep (form) (print (eval form)))
;; … then …
alfe -l ~/.autolisp -x "(ep (quote (list 1 2 3)))"
#+end_src

** Interactive REPL on CAD backends

=alfe --interactive --bricscad= (and =--autocad=) drops into a live
REPL backed by the same file-IPC protocol the batch =-x= / =-l=
actions use. Practical points:

- The prompt is =alfe>= (or =    >= for continuation lines when the
  form isn't balanced yet). Multi-line forms are accepted — the
  reader waits for a balanced parenthesis count before forwarding.
- Each form is sent through =protocol/stdin.txt=; output is drained
  live to your terminal as the CAD prints (no end-of-plan buffering).
- Errors do not exit the REPL: a failed eval surfaces its message on
  =stderr=, the prompt comes back, the runtime stays in its read-eval
  loop.

On MS-Windows, the CAD backends discover installed engines by
default from the standard =Program Files= roots. =--bricscad=
searches =%ProgramW6432%=, =%ProgramFiles%= and
=%ProgramFiles(x86)%= for =Bricsys/*/bricscad.exe=; =--autocad=
searches the same roots for =Autodesk/AutoCAD */acad.exe=,
=AutoCAD LT */acadlt.exe= and =accoreconsole.exe=. If
=BRICSCAD_EXE=, =AUTOCAD_EXE= or =AUTOCAD_ACCORECONSOLE= is set,
that explicit path wins.

For =alfe --autocad --mode batch=, the drawing/template selection is:
=--dwg FILE= first, then =AUTOLISP_DWG=, then a shipped
=Template/acadiso.dwt= or =Template/acad.dwt= next to the discovered
AutoCAD install. Only if all three miss does batch mode stop with a
=NO-DWG= bootstrap error.
- Exit with any of: Ctrl-D (EOF), an empty line that equals =:quit=,
  =:q=, =:exit=, =(quit)=, =(exit)=, or by queuing a =--quit= action.

You can mix =-l= / =-x= with =--interactive= in one invocation: the
batch actions run first, then control hands off to the REPL with the
same shared evaluation context.

* Encoding

Encoding is set per /situation/ — one option per boundary where
bytes cross. Each situation =S= has a long form =--S-encoding ENC=
and a short form =-ES ENC=; bidirectional situations also accept a
=-in= / =-out= suffix (=--S-in-encoding=, =-ES-in=). A bare
=--encoding ENC= / =-E ENC= sets every situation at once.

| Situation  | Option                | Effect                                              |
|------------+-----------------------+-----------------------------------------------------|
| source     | =-Esource ENC=        | Source-file encoding for the whole session.         |
| terminal   | =-Eterminal ENC=      | alfe's own REPL I/O encoding; surfaced to AutoLISP. |
| file       | =-Efile ENC=          | =(open …)= file I/O default.                         |
| console    | =-Econsole ENC=       | CAD GUI console device I/O.                          |
| cadstdio   | =-Ecadstdio ENC=      | CAD subprocess stdin/stdout pipes.                  |
| log        | =-Elog ENC=           | alfe's log/diagnostic stream.                        |
| (all)      | =-E ENC=              | Every situation at once.                            |

Accepted ENC values: =utf-8=, =iso-8859-1= (= =latin-1=),
=windows-1252= (= =cp1252=), =us-ascii=. Suffixes select a
line-ending variant: =-mac= / =-cr= for CR, =-dos= / =-crlf= for
CRLF, =-unix= / =-lf= for LF. So =-Esource utf-8-crlf= reads a UTF-8
file with CRLF terminators.

Without =-Esource=, the dialect's default applies (=iso-8859-1= for
=strict=, =utf-8= for =autocad-2026= / =bricscad-v26= /
=clautolisp=). When neither dialect nor option specifies one, the
process locale (=$LC_ALL=, then =$LANG=, then =$LC_CTYPE=)
supplies the fallback.

=--list-encodings= prints every accepted ENC name and exits;
=--list-situations= prints the situations and their directions.

** What each situation actually does

Not every situation is settable on every target — some are fixed by the
CAD product. alfe *accepts* the option in all cases, but when the value is
fixed it warns that it is ignored and keeps the product value (so a typo is
still an error, but a fixed boundary is never silently wrong).

- =terminal= — applied to alfe's OWN =*standard-output*= / =*standard-input*=
  / =*error-output*=. =-Eterminal-in= drives stdin, =-Eterminal-out= drives
  stdout+stderr; the bare form both. Settable everywhere (it is alfe's own
  stream).
- =source= — an explicit =-Esource= is forwarded into the CAD's native
  =(load)= so a =.lsp= with non-ASCII literals decodes correctly (BricsCAD
  =,ccs=…=, AutoCAD the =open= 3rd-arg at =LISPSYS= 1/2). Without it the CAD
  keeps its own default decode.
- =file= — the default encoding of files the AutoLISP program itself opens.
  On clautolisp it also drives =*AUTOLISP-FILE-ENCODING*=.
- =console= / =cadstdio= — how alfe DECODES the CAD's console/pipe output.
  accoreconsole is UTF-16LE, *fixed by the product* — a conflicting
  =-Econsole= is warned and ignored. For other targets the default is an
  auto-detect cascade (UTF-16LE / UTF-8 / lenient) unless you name a codec.
- =log= — alfe's own diagnostic stream.

** Per-target defaults (measured 2026-07)

These are the encodings each target exhibits with NO override — the reason
some situations warn-and-ignore. Full provenance (settable / product-fixed /
LISPSYS-selected) is tracked in the project's encoding issues.

| Target                    | source / file           | console                       |
|---------------------------+-------------------------+-------------------------------|
| clautolisp (Linux)        | UTF-8 (settable, LC_*)  | UTF-8                         |
| BricsCAD V26 / macOS      | UTF-8 under a UTF-8 locale (settable via =LC_ALL=); read needs a BOM | full Unicode (GUI) |
| BricsCAD V25 / Windows    | ANSI_1252; per-open =,ccs=UTF-8/UTF-16LE= honoured | cp1252 (GUI) |
| AutoCAD 2022 / accoreconsole | ANSI_1252 / MBCS; =LISPSYS= 1/2 → UTF-8 (restart); =ccs=~ ignored | UTF-16LE, fixed |

* Init files

On startup (unless =--no-init= / =-norc= is given), alfe loads
the first init file it finds in this order:

1. =~/.alfe= or =~/.alferc=
2. =~/.autolisp= or =~/.autolisprc=
3. =~/.config/alfe/init=
4. =~/.config/autolisp/init=

The init file runs under the selected dialect and backend; it's a
natural place to put =alref-set-root= calls, custom helpers, REPL
preferences, etc.

* The *AUTOLISP-…* globals

User AutoLISP code can read these globals to branch on session
state:

| Variable                       | Meaning                                                |
|--------------------------------+--------------------------------------------------------|
| =*AUTOLISP-FRONTEND*=          | =ALFE= when alfe is the entry point, =CLAUTOLISP= when clautolisp is invoked directly. |
| =*AUTOLISP-BACKEND*=           | The engine running user code: =CLAUTOLISP= / =BRICSCAD= / =AUTOCAD=. |
| =*AUTOLISP-HELP*=              | The --help banner of the front-end as a string.        |
| =*AUTOLISP-DIALECT*=           | =:strict= / =:autocad-2026= / =:bricscad-v26= / =:clautolisp=. |
| =*AUTOLISP-HOST*=              | =:mock= / =:null= / a CAD-specific keyword.            |
| =*AUTOLISP-FILE-ENCODING*=     | Active source-file encoding (always a string). Empty string =""= means "no preference; fall through to the dialect default" — the documented degenerate case when neither =-Esource= nor any =LC_*= env var resolves an encoding. |
| =*AUTOLISP-TERMINAL-ENCODING*= | Active terminal encoding (always a string, never empty — falls back to =US-ASCII= in the degenerate case). |
| =*AUTOLISP-VERSION*=           | Version string of the running engine.                  |
| =*AUTOLISP-LOAD-PATHNAME*=     | Set by =LOAD= during evaluation of the loaded file.    |
| =*AUTOLISP-EXPRESSION*=        | Set during evaluation of a =-x= expression.            |
| =*AUTOLISP-INTERACTIVE*=       | =T= when the REPL is active, =NIL= otherwise.          |

The specifications document the full set and their lifetimes.

* Seeing the CAD command line: =--print-command=

=--print-command= answers "what exactly does alfe launch?". It runs
the whole preparation phase for real — creates the workdir, stages the
runtime and bootstrap LSP, writes =run-common.lsp= and the launcher
(=run.scr=, or the VBScript/AppleScript bridge under
=--mode automation=) — and then, instead of spawning the CAD, prints
the command line it would have spawned:

#+begin_src sh
$ alfe --bricscad --print-command -x "(princ)"
/opt/bricsys/bricscad/bricscad -B /tmp/alfe-bricscad-31337-a1b2c3/run.scr

$ alfe --autocad --mode batch --print-command -l draw.lsp
'C:/Program Files/Autodesk/AutoCAD 2026/accoreconsole.exe' /i C:/T/tpl.dwt /s C:/T/alfe-autocad-2244-f0e9d1/run.scr
#+end_src

Exactly one line goes to stdout — the command, with every argument
quoted for the host shell — so it can be captured directly:

#+begin_src sh
cmd=$(alfe --bricscad --print-command --keep-workdir -x "(princ)")
#+end_src

Everything else (backend, workdir, the raw argv list) is logged at
=--verbose= / =--debug=.

Two things to know:

- *The workdir is deleted on the way out* unless you pass
  =--keep-workdir=. Without it the printed command names a directory
  that no longer exists — fine for reading the argv, useless for
  running it. Combine with =--keep-workdir= (and optionally
  =--write-workdir-path FILE=) when you intend to run the command by
  hand.
- *Running that command yourself is not a full alfe run.* It starts
  the CAD against the staged workdir, and the engine will boot, load
  =run-common.lsp= and reach =READY= — then wait, because nothing is
  driving alfe's side of the file-IPC protocol (no request is ever
  written to =protocol/=, no output is drained). It is a debugging
  aid: it shows the exact switches, binary and script path, and lets
  you reproduce a launch-time failure (licensing, profile, a modal
  dialog) without alfe in the loop.

=--print-command= requires a CAD backend. Under =--clautolisp= there
is no external command line — the engine runs in-process — so alfe
exits 2 with a usage error rather than printing nothing.

It is distinct from =--dry-run=, which resolves nothing, touches no
disk and just prints the action plan.

* Troubleshooting

** =alfe= prints "Backend ... is not registered"

You selected an explicit backend that isn't compiled into this
build. Usually means a CAD backend is referenced on a host build
that doesn't ship it. Pick =--clautolisp= or omit the flag for
the default.

** =alfe --bricscad= fails on Linux

BricsCAD ships for Linux but the wrapper integration is currently
macOS- and Windows-only. Track =alfe-bricscad-linux.issue=.

** =alfe --autocad= fails on macOS or Linux

AutoCAD is not distributed for those platforms. =alfe= exits with
code 3 and a clear message. Use =--bricscad= (where supported) or
=--clautolisp= instead.

** "alfe with no flags is suddenly different"

Yes — see the [[#backend-selection][Backend selection]] section.
Auto-detection of installed CADs has been removed. Set
=$ALFE_BACKEND_OVERRIDE= in your shell init if you want a CAD
backend by default.

** A long =(eval …)= on a CAD backend is aborted after ~30 s

By default the per-request timeout is *RUNNING-aware*: it bounds only
the time until the engine acknowledges the request (=RUNNING N=). Once
that acknowledgement is seen and the CAD process is alive, alfe keeps
waiting — a legitimately long computation is not killed on wall-clock,
and a dead engine still aborts promptly. If you still want a firm upper
bound (or need to raise a slow-launch handshake window), pass
=--timeout N= or set =$AUTOLISP_WAIT_SECS=N=; an explicit value is a
*hard cap* — =--timeout 1= aborts a long eval, =--timeout 600= grants it
ten minutes. (Before alfe 1.7.3 =--timeout= was parsed but ignored on
the CAD backends, so a long eval was aborted at the fixed 30 s default.)

Per the project-wide synchronisation rule (AGENTS.md, Documentation

specifications, this user-manual, or the man page must be
propagated to every track.
